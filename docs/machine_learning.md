# Machine Learning Platform

Phase 3 adds a local, explicit machine learning layer on top of the Phase 2
canonical schema and feature store.

## Scope

Implemented models:

- Risk prediction using `RandomForestClassifier`
- Customer segmentation using `KMeans`

Not implemented in this phase:

- LLMs
- RAG
- Provider switching
- Recommendation engine
- Customer intelligence generation

## Inputs

Models consume `feature_snapshots` generated by the Phase 2 feature store. The
training matrix combines canonical profile fields with engineered features such
as debt-to-income, savings ratio, spend ratio, credit utilization, loan exposure,
monthly spending, customer tenure, and risk indicators.

## Risk Labels

The public datasets do not share one common supervised financial-risk target, so
the risk model uses deterministic labels derived from financial indicators:

- Credit score bands
- Debt-to-income thresholds
- Savings ratio thresholds
- Credit utilization
- Spend ratio
- Rejected loans
- Missing income flags

This keeps the training target reproducible and explainable for an interview
demo while avoiding fake labels.

## Artifacts

Artifacts are stored as versioned `.joblib` files under `models/`. The directory
is ignored by Git because artifacts are generated locally.

Training is never automatic on startup. It is triggered explicitly through API
or UI actions.
